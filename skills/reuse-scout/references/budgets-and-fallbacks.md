# 计数与降级细则

各模式总上限以 [SKILL.md](../SKILL.md) 为准；此文解释边界，不另设一套额度。

维护简短的本次账本：模式、查询已用/上限、详情已用/上限、深入候选已用/上限、停止原因。内部计数服务于可检查报告，无需向用户展示冗长流水。

| 可见操作 | 计数 |
| --- | --- |
| 同一次调用含 3 个查询 | 查询 +3，不是 +1 |
| 同查询从网页改到 GitHub | 新的查询+渠道，查询 +1 |
| 搜索结果第 2 页 | 查询 +1 |
| Issue 评论或详情的额外分页 | 详情 +1 |
| 批量打开 4 个页面/远程文件 | 详情 +4 |
| 重新抓取已读 URL、失败重试 | 对应详情或查询仍 +1 |
| 搜索响应原已带出的字段 | 不再加详情；无需重新请求同字段 |
| 搜索调用自动额外抓取独立详情 | 查询与可见独立详情分别计入；仅通过本次只读工具的参数关闭额外抓取，无法控制则停止使用该工具并报告限制，不修改宿主或 MCP 配置 |
| 只读相关本地文件/用户已经提供的摘录 | 不耗外部预算，不将摘录假装成新检索 |
| 比较新的方案的功能、许可、版本与适配成本 | 深入候选 +1；同一候选补充证据不重复占名额，远程读取仍计数 |

每次调用前按工具输入的所有子项检查预算。剩余查询 1 时不能发一个含 3 查询的批次；达到详情上限时不能继续打开已知 URL。候选上限用尽后只完善已选候选，不开启新方案深入调查；关键判断还无证据则收敛。
预算不随换路线、换渠道或重新措辞而重置。只有用户明确扩大本次范围/额度后才按新授权调整并报告，不因多轮自然对话自动清零。

快速模式用于窄问题，通常 1—2 个候选；标准适用于一般工程研究；深入只扩大数量，不扩大执行权限。离线只使用当前范围内本地材料和已给资料，不验证远程链接是否在线。

## 渠道故障

- 工具不存在：用已有只读替代能力或说明未覆盖，别自动安装。
- 未登录/权限不足：描述具体限制，不读取凭证或执行登录；有相容公开来源才继续。
- 网络失败：记失败与消耗；不要写“无匹配结果”。
- 429/限流：读取已返回的限流说明，停止该渠道，不循环等待重试、不轮换账号；有可用公开替代且还有预算才考虑一次必要查询。
- 403：可能是授权也可能是限流；依据返回信息分类，无法确定就写原因未确认。

停止后输出剩余未知项及能解除它们的最小步骤。数量是纯 Skill 的行为约束，不能声称程序拦截、精确 Token 限制或保证节约成本。
