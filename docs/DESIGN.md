# Reuse Scout 设计与实施计划

设计日期：2026-09-13。用户后续要求增补为 Codex 与 Claude Code 优先；本公开文档保留设计与产品边界。

## 选择

采用独立、纯指令的 Agent Skills 目录，首批适配 Codex 和 Claude Code。一份公共研究流程配合各宿主调用策略：Codex 使用 openai.yaml，Claude Code 使用 SKILL.md frontmatter。两字段共存需在各真实宿主确认解析效果，不据结构宣称所有 Agent 兼容。不需要自建模型 API、搜索服务或数据库，不宣称优于上游。

安装边界为 `skills/reuse-scout/`。运行时只使用宿主已有能力，不要求 Python、额外密钥、CLI、MCP 或子 Agent。开发中的独立审阅不属于产品运行流程。

## 输入与输出

输入：工程目标或故障、当前项目、版本/平台、联网与隐私限制，以及快速/标准/深入/离线自然语言模式。能从本地确认的事实不重复询问；默认标准模式、只研究。

流程：确认范围 → 本地只读 → 本地足够则停止 → 选择功能复用或故障调查路线 → 按预算收集直接证据 → 判断硬约束和适配条件 → 输出结论、最小方案和验证计划。混合任务选主路线，共享一次预算，不分别重置。

输出：默认对话内的简短报告。分别记录本地静态/上游直接证据、适配推断或证据不足，以及执行状态；未执行写明未执行，本地验证通过仅用于有真实执行记录的检查。保存报告须由用户指定或授权路径。

搜索预算（查询/详情/深入候选）为快速 3/5/2、标准 6/12/3、深入 12/24/5、离线 0/0/已有材料。失败、分页、批量子项计数，调用前核对剩余额度；这是行为约束，不是硬 Token 限额或安全沙箱。

## 文件职责

下列开发校验工具和测试描述原始设计；当前公开分支只保留技能源码与展示资料，不包含这些内部文件。

- `SKILL.md`：调用边界、模式预算、主路线、停止与安全底线。
- `references/feature-reuse.md`、`bug-investigation.md`：仅所选路线需要的判断。
- `references/evidence-and-safety.md`、`budgets-and-fallbacks.md`：需要深入证据、脱敏或计数/降级时读取；核心底线保留在入口。
- `assets/report-template.md`：详细报告槽位；不预填真实验证结果。
- 仓库 `examples/`：明确标记为虚构且未运行的示例；不会默认加载到技能。
- `tools/validate_skill.py`：Python 3.9+ 离线包结构校验；PyYAML SafeLoader 与 markdown-it-py 仅开发依赖。不自写 YAML 解析器。
- `tests/test_validate_skill.py`：临时合成包正负例，验证真实返回结果和 CLI 退出码。
- `tools/build_release.py`：先校验源与版本，再按明确文件清单生成本地 ZIP 和 SHA-256；拒绝额外文件、链接和覆盖已有产物，不上传。
- `tests/test_build_release.py`：在合成目录核对版本匹配、成员清单、字节与摘要，以及输入拒绝和失败回滚。
- `docs/EVALUATION.md`：定义行为评估方法；执行记录属于开发过程资料。

## 实施顺序

1. 保留任务文件，记录非 Git 目录状态及上游核对。先记录无技能的合成基线；基线未失败也如实记载，不据此宣称改进。
2. 编写合成有效包与缺文件、类型错误、缩进、字符串 false、重名、链接逃逸/断链、伪验证、许可不一致负例；先运行暴露未实现状态。
3. 实现 `validate(repo_root: Path) -> list[str]`，空列表代表结构通过；CLI 默认检查本仓库，`--root` 可指定临时仓库，错误返回 1，依赖/参数错误返回 2。
4. 编写技能与说明；校验只检查显式结构和有限字符串，不将其描述为行为验证或泄密保证。
5. 执行离线测试、打包后引用检查、合成场景复核与差异空白检查。尝试不修改真实配置的新 Codex 会话；无法建立隔离基线/轨迹时将宿主行为记为未验证。
6. 独立审阅内容与校验器，修复实际问题，记录最终平台、版本、命令、结果和未测项。

## 范围与验收边界

不开发前端、数据库、Agent 编排、自动安装器、后台服务或全局 Hook。不修改业务项目代码、锁文件或配置；执行验证与后续实施须转入用户已授权的普通开发流程。

结构检查不能证明宿主发现、手动调用、隐式禁用、预算遵循或只读行为。真实验收需新会话、合成工作区、工具轨迹及前后文件快照，分别记录 Codex 和 Claude Code。Linux/CI 矩阵只有实际运行后才能记为通过；无 Token 用量就不报告精确节省。公开文档仅使用克隆相对路径、交互输入和宿主约定路径，不包含作者机器位置。GitHub 发布需用户另行明确允许。

## 长期维护约束

只维护 `skills/reuse-scout/` 公共源；Codex 的 `policy.allow_implicit_invocation: false` 与 Claude Code 的 `disable-model-invocation: true` 分别声明手动调用。共同解析由真实宿主验收，不从字段存在推断兼容。

修改校验器时先补能检出缺陷的正负例，保留 `validate(repo_root: Path) -> list[str]` 接口及 CLI 退出码。description 的 1024/1025 字符边界、可选 compatibility 的 1—500 字符及类型、可选 license 非空字符串、两宿主布尔策略均属于回归范围。

打包测试核对明确成员、包内版本与命令参数一致、解包字节及 SHA-256；额外文件、链接、重复输出与损坏输入不能产生可误用的包。开发检查使用合成临时数据，不依赖用户配置、认证或本地加载副本。

## 0.2.0-preview.1 的增量约束

第二版维持纯指令技能、九文件分发包和现有 Python 接口，不增加运行时依赖。外部查询可包含必要且脱敏的功能、API、语言、运行时和平台；关键结论核对直接来源，搜索摘要仅作线索。报告中的证据性质与执行状态分别表达。

校验器在真实路径边界检查之外，按包内实际相对文件名精确检查引用，避免 Windows 的大小写或尾随点别名掩盖跨平台断链。YAML 构造异常与 CLI 参数错误均使用受控脱敏输出。固定合成验收资料只服务开发与评估，不随技能打包，也不自动形成宿主通过结论。
